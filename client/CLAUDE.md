# CLAUDE.md — веб-клиент

Инструкции для агента, работающего с `client/`. Общие правила репозитория — в корневом
`CLAUDE.md`, здесь только то, что касается клиента.

## Что это

SPA на React. Собирается в статику и отдаётся nginx — отдельным контейнером, не бэкендом.
Серверного рендеринга нет и не планируется: вход в приложение за авторизацией, индексировать
нечего.

Стек: Vite, React, TypeScript (strict), React Router, TanStack Query, Tailwind, Vitest.

## Команды

```bash
npm run check      # типы + линт + формат + тесты, одной командой
npm run dev        # dev-сервер на 5173, /api проксируется на localhost:5023
npm run lint:fix   # починить то, что чинится автоматически
npm run format     # отформатировать
npm run build      # сборка в dist/
```

`npm run check` — то, что должно быть зелёным перед коммитом. Отдельные шаги (`typecheck`,
`lint`, `format:check`, `test`) существуют, чтобы понять, что именно упало.

Бэкенд для `npm run dev` поднимается отдельно: `dotnet run --project src/DocsFlow.Api`.
Без него фронт работает, но запросы к `/api` возвращают ошибку.

## Архитектура: Feature-Sliced Design

Код разложен по слоям. Слой импортирует только те, что ниже него, и только через public API
слайса — его `index.ts`.

| Слой       | Что в нём                                           | Импортирует                                 |
| ---------- | --------------------------------------------------- | ------------------------------------------- |
| `app`      | Инициализация: провайдеры, роутер, глобальные стили | все нижние                                  |
| `pages`    | Страницы под маршруты                               | `widgets`, `features`, `entities`, `shared` |
| `widgets`  | Самостоятельные блоки UI из нескольких фич          | `features`, `entities`, `shared`            |
| `features` | Пользовательские сценарии                           | `entities`, `shared`                        |
| `entities` | Бизнес-сущности                                     | `shared`                                    |
| `shared`   | Код без привязки к предметной области               | `shared`                                    |

Два запрета, которые чаще всего нарушают:

1. **Слайсы одного слоя не видят друг друга.** `features/search-documents` не может
   импортировать `features/upload-document`. Общий код поднимается слоем ниже.
2. **Внутрь чужого слайса ходить нельзя.** Только `@/shared/api`, никогда
   `@/shared/api/http-client`. Нужное наружу — реэкспортируется из `index.ts`.

Это не соглашение на словах: оба правила проверяет ESLint (`boundaries/dependencies`), и
нарушение валит `npm run check`. Подробности каждого слоя — в `README.md` внутри его папки.

## Как добавить фичу

```
src/features/upload-document/
  api/upload-document.ts     запрос через apiFetch из @/shared/api
  model/use-upload.ts        хук поверх useMutation
  ui/UploadButton.tsx        компонент
  index.ts                   export { UploadButton } from './ui/UploadButton'
```

Дальше фича вставляется в страницу или виджет — одним импортом `@/features/upload-document`.

Сегменты заводятся по мере надобности: если у фичи нет своего состояния, папки `model` быть
не должно. Пустые папки и слайсы «про запас» не создаём.

## Данные с сервера

Только через `apiFetch` из `@/shared/api` и только внутри `useQuery`/`useMutation`.
Прямой `fetch` в компоненте и связка `useEffect` + `setState` для загрузки — не используются:
кеширование, повторы и состояние загрузки уже решены в TanStack Query.

Базовый путь — относительный `/api`. Абсолютных адресов бэкенда в коде нет: в dev запросы
проксирует Vite, в проде — nginx. Поэтому CORS не нужен.

Типы ответов пока описываются руками. Когда у API появятся эндпоинты, их место займёт
генерация из OpenAPI — до тех пор описанный руками тип это временная мера, а не образец.

## Тесты

Vitest + Testing Library, файл рядом с кодом: `HomePage.tsx` → `HomePage.test.tsx`.
Проверяется поведение через то, что видит пользователь (`getByRole`, `getByText`), а не
внутреннее состояние компонента. Импорты `describe`/`it`/`expect` — явные, глобалов нет.

## Соглашения

- Компоненты — `PascalCase.tsx`, всё остальное — `kebab-case.ts`.
- Импорты внутри `src` — через алиас `@/`, относительные пути только внутри своего слайса.
- Комментарии — русские, идентификаторы — английские (правило репозитория).
- Стили — классы Tailwind в разметке. Отдельные `.css` заводятся, только если задачу нельзя
  решить классами.

## Чего в каркасе намеренно нет

Не додумывать и не добавлять молча — это открытые вопросы, а не забытые:

- **Авторизация.** Интеграция с Keycloak делается отдельно; как SPA получает токен — решается
  там, а не здесь.
- **Генерация клиента из OpenAPI.** Ждёт первых эндпоинтов у API.
- **UI-кит.** Пока примитивов мало, они живут в `shared/ui`. Выбор библиотеки — отдельное
  решение владельца.
- **E2E-тесты.** Playwright не подключён.
