# CLAUDE.md

Инструкции для агента, работающего с этим репозиторием.

## Проект

Публичный сервис хранения, автоматической классификации и интеллектуального поиска по личным
документам. Пользователь приходит из интернета и регистрируется сам, загружает файл в любом виде
(фото, скан, PDF), система распознаёт, классифицирует, индексирует и отдаёт двумя способами:
полнотекстовый поиск и вопрос на естественном языке с обязательной ссылкой на первоисточник.
Документы живут в space: владелец создаёт space и подключает к нему других пользователей.

Клиент — веб-приложение в этом же репозитории, ещё не начато. Мобильных клиентов пока нет.

Кодовое имя не финализировано. В коде используется `DocsFlow`.

## Статус

Ранняя стадия: собирается инфраструктурный слой, продуктовой функциональности пока нет.

Источник требований — прямые указания владельца в задаче. Прежняя база заметок в Notion
(«Family Vault») неактуальна: она описывала приватный семейный архив и на неё опираться нельзя.
Принятые решения фиксируются спеками в `docs/superpowers/specs/`.

## Структура

```
src/DocsFlow.Api/                ASP.NET Core приложение: конвейер аутентификации и эндпоинты
src/DocsFlow.Storage/            объектное хранилище: IObjectStorage + реализация поверх S3
src/DocsFlow.Database/           доступ к Postgres: IDbConnectionFactory + Dapper
src/DocsFlow.Database.Migrator/  раннер миграций FluentMigrator (отдельный процесс)
src/DocsFlow.Users/              пользователи: модель, репозиторий, провижининг при входе
infra/                           конфигурация окружения: realm Keycloak, init-скрипты Postgres
tests/                           интеграционные тесты (Testcontainers)
```

Версии пакетов — только в `Directory.Packages.props` (CPM). Общие свойства проектов —
в `Directory.Build.props`. В отдельных `.csproj` версии и `TargetFramework` не дублируются.

## Команды

```bash
docker compose up -d      # локальное окружение, только в основном репозитории
dotnet build
dotnet test               # поднимает свои контейнеры, compose для этого не нужен
```

Локальное окружение — MinIO, Postgres, Keycloak и Mailpit; подробности в разделе «Окружение».

## Параллельные сессии

Над проектом одновременно работают несколько агентов, каждый в своём git worktree. Основной
репозиторий `~/pet/docs-flow` для работы над задачами не используется.

| Ветка | Роль |
|---|---|
| `master` | Стабильная. Агенты её не трогают: ни коммитов, ни push. |
| `dev` | Интеграционная. Сюда вливается вся работа. |
| `<область>/<тема>` | Рабочая ветка одной задачи в одном worktree. |

`dev` → `master` вливает владелец вручную.

### Начало задачи

```bash
git -C ~/pet/docs-flow fetch origin
git -C ~/pet/docs-flow worktree add ../docs-flow-<тема> -b <область>/<тема> origin/dev
```

Ветки — `<область>/<краткое-описание>` в kebab-case: `storage/presigned-upload`,
`api/upload-endpoint`. Один worktree — одна задача.

### Синхронизация

Перед началом работы и дальше регулярно, как минимум — перед интеграцией:

```bash
git fetch origin
git merge origin/dev
```

Именно merge, не rebase: история ветки выходит шумнее, зато push никогда не переписывает то,
что уже ушло в origin, и параллельные сессии не наступают друг другу на ноги.

### Интеграция

Точка сборки — `origin/dev`, а не локальная ветка. Одну ветку нельзя держать в двух worktree
сразу, поэтому локальный `dev` в лучшем случае есть у кого-то одного и опираться на него нельзя.

```bash
git fetch origin && git merge origin/dev      # конфликтов быть не должно
dotnet build && dotnet test                   # обязательно зелёные
git push origin HEAD:dev
```

Push отклонён, потому что кто-то влил раньше — повторить цикл с начала. Не форсить.

После интеграции убрать за собой:

```bash
git -C ~/pet/docs-flow worktree remove ../docs-flow-<тема>
git -C ~/pet/docs-flow branch -d <область>/<тема>
```

### Окружение

Стек поднимается **только в основном репозитории** и один на все worktree: MinIO (9000/9001),
Postgres (5432), Keycloak (8080), Mailpit (1025 SMTP и 8025 веб-интерфейс). В worktree
`docker compose up` не запускать: порты уже заняты, второй стек не встанет. Конфигурация в
`appsettings.Development.json` одинакова во всех worktree и указывает на те же адреса.

`dotnet test` от этого не зависит — Testcontainers поднимает свои Postgres, MinIO и Keycloak
на свободных портах, поэтому тесты из разных worktree идут параллельно и не мешают друг другу.

Про Keycloak стоит знать три вещи:

- **База `keycloak`** живёт в том же инстансе Postgres и создаётся скриптом из
  `infra/postgres/init`. Скрипт исполняется только при инициализации **пустого** тома, поэтому на
  уже существующем `postgres-data` базу нужно создать руками:
  `docker compose exec postgres createdb -U docsflow keycloak`.
- **Realm импортируется только если его ещё нет.** Правки в `infra/keycloak/realm-export.json` на
  созданный realm не влияют — либо менять настройку в админке, либо удалять базу `keycloak`.
- **Письма никуда не уходят**: подтверждение email и восстановление пароля читаются в Mailpit на
  http://localhost:8025.

Подробнее — `infra/keycloak/README.md`.

## Продуктовые принципы

Не декларация — каждый пункт отсекает конкретные технические решения.

| Принцип | Что запрещает на практике |
|---|---|
| Приватность по умолчанию | Вызов внешнего API с пользовательскими данными, который нельзя выключить конфигом |
| Provider-agnostic | Обращение к SDK вендора из бизнес-логики в обход адаптера |
| Деградация, а не отказ | Падение сценария при недоступности внешнего OCR или LLM |
| Оригинал — источник истины | Мутация исходного файла; хранение производных данных как невосстановимых |
| Никаких ответов без ссылки | Ответ LLM без локатора документа и фрагмента |
| Изоляция данных арендатора | Запрос к данным без фильтра по владельцу или членству в space; идентификатор арендатора, взятый из тела запроса, а не из аутентифицированной сессии |

## Правила работы

1. Не добавлять зависимости и инфраструктурные компоненты без согласования.
2. Не додумывать нерешённые детали — задавать вопрос.
3. Идентификаторы и имена файлов — английские; комментарии и XML-doc — русские.
